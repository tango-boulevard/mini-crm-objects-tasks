# Чек-лист сдачи

## Перед демонстрацией

- Docker Desktop запущен.
- `npx supabase start` показывает работающий локальный стек.
- `.env.local` содержит локальные Project URL и Publishable key.
- `npm run check` завершается успешно: 5 frontend-тестов и production build.
- `npx supabase test db` завершается успешно: 15 database-тестов.
- `git status --short` не показывает незакоммиченных файлов.

## Сценарий демонстрации

1. Войти как постановщик и показать список объектов.
2. Создать задачу и назначить исполнителя.
3. Войти исполнителем, открыть «Мои задачи» и перевести задачу в работу.
4. Отправить задачу на проверку.
5. Войти постановщиком, принять задачу и показать историю статусов.
6. Коротко показать миграции, RLS-политики и pgTAP-тесты.

## Короткое объяснение решения

Frontend отвечает за интерфейс и валидацию формы. Supabase Auth выдаёт пользовательскую сессию. PostgreSQL хранит данные, а RLS ограничивает строки по роли и назначению. Переход статуса выполняет серверная RPC-функция в одной транзакции: она проверяет роль, разрешённый переход и одновременно записывает историю.

## Осознанные ограничения

- Управление пользователями выполняется администратором через Supabase, самостоятельной регистрации нет.
- Комментарий обязателен только при возврате задачи на доработку.
- Автоматизированные browser E2E-тесты не добавлены; критический сценарий проверен вручную, а бизнес-правила покрыты frontend- и database-тестами.
- Деплой в облачный Supabase и на frontend-хостинг не выполнялся, потому что для тестового задания достаточно воспроизводимого локального запуска.
