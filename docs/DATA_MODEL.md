# Модель данных

## 1. Перечисления

### app_role

- `manager`
- `executor`

### task_status

- `new`
- `in_progress`
- `in_review`
- `accepted`
- `needs_revision`

Значения базы остаются стабильными машинными идентификаторами. Русские подписи задаются во frontend.

## 2. Таблица profiles

| Поле | Тип | Правило |
|---|---|---|
| id | uuid | PK, FK на `auth.users(id)`, без каскадного удаления в рабочей среде |
| display_name | text | обязательно, непустое значение |
| role | app_role | обязательно |
| is_active | boolean | по умолчанию `true` |
| created_at | timestamptz | серверное время |
| updated_at | timestamptz | серверное время |

Роль и активность изменяются только административным процессом, отсутствующим в публичном клиенте.

## 3. Таблица construction_objects

| Поле | Тип | Правило |
|---|---|---|
| id | uuid | PK, генерируется базой |
| name | text | обязательно, после trim не пусто |
| address | text | обязательно, после trim не пусто |
| created_by | uuid | FK на `profiles`, определяется сервером |
| created_at | timestamptz | определяется сервером |
| updated_at | timestamptz | определяется сервером |

Удаление запрещено, пока существует хотя бы одна связанная задача.

## 4. Таблица tasks

| Поле | Тип | Правило |
|---|---|---|
| id | uuid | PK, генерируется базой |
| object_id | uuid | FK на объект, обязательно, `ON DELETE RESTRICT` |
| title | text | обязательно, после trim не пусто |
| description | text | обязательно; может быть пустой строкой только если это будет принято отдельно |
| assignee_id | uuid | FK на профиль исполнителя, обязательно |
| status | task_status | серверное значение `new` |
| created_by | uuid | FK на профиль постановщика, определяется сервером |
| created_at | timestamptz | определяется сервером |
| updated_at | timestamptz | определяется сервером |

Проверка роли назначенного пользователя выполняется серверной функцией или триггером, поскольку обычный `CHECK` не должен обращаться к другой таблице.

## 5. Таблица task_status_history

| Поле | Тип | Правило |
|---|---|---|
| id | bigint identity | PK |
| task_id | uuid | FK на задачу, обязательно |
| from_status | task_status | `NULL` только для создания |
| to_status | task_status | обязательно |
| changed_by | uuid | FK на профиль, берётся из `auth.uid()` |
| changed_at | timestamptz | серверное время |
| comment | text | обязательный непустой текст для `needs_revision` |

Для клиентских ролей таблица доступна только на чтение в пределах видимых задач.

## 6. Индексы

- `tasks(object_id)` для карточки объекта;
- `tasks(assignee_id, status)` для списка исполнителя;
- `tasks(created_by)` для аудита и возможных выборок постановщика;
- `task_status_history(task_id, changed_at, id)` для стабильной хронологии;
- частичные или дополнительные индексы добавляются только после подтверждения реального запроса.

## 7. Временные метки

Все даты хранятся как `timestamptz` в UTC. Отображение выполняется в локальной временной зоне браузера. `updated_at` меняется серверным триггером, а не значением клиента.

## 8. Имена и зарезервированные слова

Таблица объектов называется `construction_objects`, а не `objects`, чтобы избежать слишком общего имени и двусмысленности в коде. Пользовательские роли называются `manager` и `executor`, что отделяет предметную роль постановщика от административных ролей Supabase.
