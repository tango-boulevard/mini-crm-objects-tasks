# Развёртывание для сдачи

Рекомендуемая схема: GitHub, облачный Supabase и Vercel.

## 1 Репозиторий GitHub

Создайте пустой репозиторий без автоматически сгенерированных README и `.gitignore`, затем выполните:

```powershell
git remote add origin https://github.com/USERNAME/mini-crm-objects-tasks.git
git push -u origin master
```

Репозиторий должен быть публичным либо работодателю нужно выдать доступ.

## 2 Облачный Supabase

1. Создайте отдельный бесплатный проект Supabase для демонстрации.
2. Отключите открытую регистрацию по email в настройках Auth.
3. Свяжите локальный проект и примените миграции:

```powershell
npx supabase login
npx supabase link --project-ref PROJECT_REF
npx supabase db push
```

4. Создайте в Supabase Auth минимум одного постановщика и двух исполнителей.
5. Для каждого Auth UUID добавьте строку в `public.profiles` с ролью `manager` либо `executor`.
6. Добавьте 2–3 объекта и несколько задач в разных статусах через приложение.

Локальный `seed.sql` содержит демонстрационные пароли и предназначен только для локального окружения. Для публичного стенда используйте отдельные пароли и не коммитьте их.

## 3 Vercel

1. Импортируйте GitHub-репозиторий в Vercel как Vite-проект.
2. Добавьте переменные окружения `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.
3. Команда сборки: `npm run build`. Каталог результата: `dist`.
4. `vercel.json` направляет прямые URL клиентских маршрутов в `index.html`.
5. Выполните deploy и откройте выданный HTTPS-адрес.
6. В Supabase Auth добавьте URL приложения в Site URL и Redirect URLs.

В Vercel и frontend нельзя добавлять `service_role`, secret key или Supabase access token.

## 4 Проверка опубликованного стенда

- Вход работает для всех трёх пользователей.
- Постановщик видит все объекты и задачи.
- Первый исполнитель не видит задачи второго.
- Переходы работают только для разрешённой роли.
- Возврат на доработку требует комментарий.
- История содержит пользователя, время, переход и комментарий.
- Прямые ссылки открываются после перезагрузки.
- В браузерной консоли нет ошибок и секретных ключей.
